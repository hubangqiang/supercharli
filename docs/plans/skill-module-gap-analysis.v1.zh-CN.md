# Skill 模块现状差距清单 v1（中文）

对应规范：`docs/plans/skill-module-spec.v1.zh-CN.md`

## 总览
当前实现已经有“注入观测 + 管理库 + 质量回写 + 生命周期降级雏形”，但完整生命周期与发布治理还未闭环。

## A. 已完成
1. Skill 与 Memory 分层已具备
- Skill 管理库与 Memory（L1/L2）分开存储。

2. Meta 路由基础已具备
- 优先由模型在候选 skill 中选择（失败时本地兜底）。

3. 用户侧隐性机制已具备
- 对话默认不暴露 skill 生命周期与内部路由细节。

4. 基础质量闭环已具备
- 每轮有质量评分，低质量可触发一次修复重试。
- skill 使用结果回写质量分，并支持 active -> shadow 降级。

5. 观测基础已具备
- Observer 可查看注入目录/历史与管理 skill 目录/历史。

## B. 部分完成（需增强）
1. 生命周期状态不完整
- 已有 active/shadow，但 candidate/deprecated/archived 尚未真正流程化。

2. 版本治理不完整
- 有 version 字段，但缺少发布记录、版本比较、回滚链路。

3. 质量指标不完整
- 目前主要是单轮质量分，缺少按 skill 聚合趋势、分场景表现、长期漂移检测。

4. 路由解释性不足
- 有 route reason 记录，但缺少“为何选中/为何未选中”的结构化原因。

5. 注入预算治理不完整
- 已有 injectionBudget 字段，但还未形成全局预算调度与压缩策略。

## C. 未完成（v2 重点）
1. 发布流水线
- candidate -> shadow -> active 的自动化门控与人工审核接口。

2. 技能去重与合并
- 语义重复 skill 的自动合并与引用迁移。

3. 弃用与归档机制
- deprecated/archived 的触发条件、保留策略、恢复策略。

4. 安全与合规策略
- 针对高风险 skill 的专门审核与禁用策略。

5. Skill 级 AB/灰度实验
- 按会话或用户分流验证 skill 新版本收益。

## D. 推荐下一步（执行优先级）
1. 先补发布流水线（candidate/shadow/active）
2. 再补版本发布与回滚记录
3. 再补 skill 质量趋势面板和阈值告警
4. 最后补弃用归档与技能合并
