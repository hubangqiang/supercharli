# SuperCharli 开发模式

## 核心定位
SuperCharli 不能演化成本地“伪模型”。
它是本地数据与治理层，用来放大外部大模型能力。

## 职责分工
1. 外部大模型负责：
- 理解、推理、综合、生成。
- 随时间迭代能力上限。

2. 本地运行时负责：
- 数据主权（记忆本地化）。
- 标准注入（人格、约束、方法、领域标准）。
- 学习筛选（门控、审计、回滚），而非替代模型学习本体。
- 跨会话、跨模型连续性。

## 工程规则
1. Prompt/Context 优先：
- 可复用标准以本地结构化数据保存。
- 按相关性按需注入模型上下文。
- 不把业务答案写成本地固定模板。

2. Data 优先：
- 只沉淀长期可复用、可验证信号。
- 不沉淀一次性闲聊和高噪声信息。

3. Policy 优先：
- 本地逻辑只做质量与安全门控。
- 每次学习生效都必须可解释、可回滚。

4. Model-agnostic 优先：
- 同一套本地记忆与标准可驱动不同模型。
- 切换 provider 不应破坏身份连续性。

## 反模式清单
以下行为不得作为默认实现：
- 本地固定回复脚本伪装“学习结果”。
- 本地确定性问答替代模型推理。
- 通过硬编码人格绕过模型生成。

## 一句话原则
SuperCharli 本地代码负责数据治理与连续性，智能本体始终由外部大模型承担。
